## Granola connection contract

Accord uses Granola's fixed [Streamable HTTP MCP endpoint](https://docs.granola.ai/help-center/sharing/integrations/mcp). Public [resource metadata](https://mcp.granola.ai/.well-known/oauth-protected-resource/mcp) and [authorization server metadata](https://mcp-auth.granola.ai/.well-known/oauth-authorization-server) identify the issuer, endpoints, S256 PKCE and public dynamic client registration. Metadata discovery and real dynamic registration succeeded from the private Site. Consent and the OAuth callback are still unverified.

Each person authorizes their own account. OAuth state is random, hashed, owner-bound, expiring and usable once. The PKCE verifier and credentials are encrypted with AES-GCM using a server secret, distinct purposes and authenticated owner identity. Tokens are never returned to the browser. Production has a managed secret named `ACCORD_CONNECTION_ENCRYPTION_KEY`; missing or invalid configuration fails closed. Its secure recovery is required alongside any database restoration. Do not regenerate it to repair an unrelated failure.

The adapter permits only account information and three meeting-reading tools, discovers their actual schemas, and rejects unsupported filters and tool names. Fixed destinations, redirect rejection, timeouts and byte bounds constrain upstream requests. The OAuth issuer's access scope remains Granola-controlled; Accord's read-only tool allowlist is an application restriction, not a narrower provider consent scope. Account plan, workspace and administrator policy can limit available notes.

Connection generations prevent late registration or callback work from surviving disconnection. Token refresh acquires an owner/connection-bound database lease before calling the provider. Concurrent refresh attempts do not share a rotating token; failed or abandoned dispatched refresh attempts require fresh authorization. Disconnection removes Accord's stored credentials and unshared previews, cancels pending authorization and blocks later reads. It does not claim upstream token revocation or erasure of previously shared copies.

Reading creates an encrypted private preview with a 20-minute application expiry. Expired previews cannot be shared and are removed opportunistically during subsequent connection setup; there is no scheduled storage cleanup. A person chooses the destination space, title and edited excerpt before sharing. Current membership and current connection are checked at commit. Sharing creates one attributable source and clears the full preview content; identical retries recover the saved receipt, and changed retries conflict. The selected excerpt is an imported copy. It does not continuously sync, follow later Granola deletion, or automatically become accepted guidance. Existing shared-source withdrawal controls apply.

## Granola recovery contract, October 6, 2026

Connection actions validate exact same-origin and JSON headers, then read at most 128 KiB within a five-second total upload deadline before loading the authenticated service. The larger envelope accepts the full 18,500-character reviewed excerpt even when JSON escaping uses six bytes per character. Early rejection and cancellation do not await an uncooperative stream source, and incoming chunks do not extend the deadline.

Connect, tool discovery and preview share one 18-second upstream workflow budget created at HTTP entry, so elapsed upload and authentication time reduces the remaining provider budget. Each provider request has at most twelve seconds for both headers and body, further limited by the workflow's remaining time; pagination, initialization and token refresh do not reset it. Callback completion likewise shares one budget across token exchange, MCP discovery and account verification. Budget checks prevent starting a pending OAuth flow, storing a private draft or completing a new connection after expiry. These are provider-work bounds, not a deadline guarantee for authentication, SQL, encryption or the entire HTTP response. Durable writes are awaited rather than raced, and sharing/disconnection keep their existing write and receipt behavior.

Refresh recovery distinguishes whether a request was dispatched. If the budget expires before dispatch, only that attempt's lease is released and credentials remain intact. A successfully received rotating token is encrypted and persisted through the existing guarded update even if the budget expires during local persistence; later provider work then stops. A failed or lost dispatched refresh requires new sign-in instead of reusing a possibly rotated token. HTTP 401 during connected-account reads and an expired credential without a refresh token transition the matching connection to `reauth_required`, clearing credentials and its account label. The transition compares the exact connection ID and encrypted credential and requires no refresh in progress, so a late failure cannot erase a newer sign-in or another refresher; changed state returns a recoverable conflict.

Status loading and failed or empty reading catalogs offer explicit **Retry**, without automatically replaying a prior OAuth or token attempt. A catalog HTTP 401 directs the person to close the dialog and sign in again. The local [Granola recovery record](verification/granola-recovery-oct6.json) covers 326 passing project tests, including 49 new tests and 68 targeted Granola/loading-lifecycle tests, with type checking and package validation passing. The current browser check is waiting for a Chrome popup to close. These tests use synthetic providers and clocks; they do not establish actual Granola consent, callback or note reads, or native Claude/Grok/Muse exchanges. The historical live connection-start evidence below remains limited to metadata and registration.

## Personal-agent setup

[dots documentation](https://learn.chatgpt.com/docs/dots/computers-and-apps) describes using supported plugins enabled for its account. Accord offers setup instructions for that path; it does not control a person's dot or write its private memory. A provider profile only organizes Accord participation and is not an independently credentialed agent.

All assistant setup now begins with **Connect your assistant**. Provider recipes choose Claude's uploadable plugin, Grok Bot's custom remote server, Muse's Custom Connector request, the existing OpenAI plugin or another compatible remote MCP client. Exact profile selection and real authenticated calls remain required. Instinct stays conditional because its public documentation does not establish an inbound MCP contract.

Meta's [consumer Muse help](https://www.meta.com/help/artificial-intelligence/1687253048996149/) describes asking Muse to create a Custom Connector when a service is absent. That private route is separate from reviewed [directory submission](https://muse.ai/platform). Its transport and OAuth compatibility with Accord still require verification. Muse Code and Meta Model API documentation are separate products.
